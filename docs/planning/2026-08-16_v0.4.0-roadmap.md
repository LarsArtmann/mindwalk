# v0.4.0 Roadmap — post-Pareto follow-ups

> Captures the next batch of work surfaced by the post-merge status
> report at `docs/status/2026-08-16_09-28_pareto-plan-executed-end-to-end.md`.
> Roughly ordered by impact-per-hour.

## Theme

The Pareto plan closed the v0.3.0-era adapter gaps (OutcomeKnown,
cross-message result pairing, agent-graph disk cache, schema↔TS
parity, lint hygiene). v0.4.0 picks up the next layer: user-visible
observability improvements (todos), streaming refactors that the
plan documented but did not execute, and the guided-tour UX work
that was the M11 carry-over.

## Tracks

### Track 1 — todos in the data model

A real Crush session with `todos` rows in the SQLite schema does not
exist in the committed fixture; the spike test confirms the SDK path
works but UI surface is premature. When a real session arrives:

1. Add `model.SessionMeta.TodoCount int` (`model.SessionMeta`).
2. Add `model.SessionMeta.Todos []Todo` carrying the typed
   `crushdata.Todo` slice (or wrap it behind an adapter-local alias
   if the upstream type is unstable).
3. Add `todoCount` + `todos` to `schema/trace.schema.json`.
4. Mirror both fields in `web/src/types.ts Trace`.
5. Update `TestTraceSchemaParityWithTypesScript` to assert both.
6. Add an "in-progress task list" panel in the UI, separate from
   user-message marks, so reviewers can see what the agent was
   working on at each timeline beat.

Estimated: 4-6 hours including UI iteration.

### Track 2 — streaming message decoder (T28 follow-up)

The plan documented the `DB.IterMessages` refactor as "real work,
not done". Track 2 implements it:

1. Restructure `Parse` (`internal/adapter/crush/sessions.go`) to
   two passes: first pass streams messages and records every
   `tool_call.ID` with its timestamp; second pass streams again
   and resolves `tool_result.ToolCallID` matches → emits events
   lazily. Eliminates the whole-message-slice allocation.
2. Add a benchmark on a 50k-message synthetic session to quantify
   the memory peak win (the existing `BenchmarkFixtureParse` runs
   on a small fixture).
3. Replace the T28 trade-off doc with the chosen architecture in
   `AGENTS.md` and `docs/crush.md`.

Estimated: 3-4 hours.

### Track 3 — guided tour (M11 carry-over, T32 follow-up)

`web/src/ui/CheatSheet.tsx:6` already exposes an `onReplayTour`
stub. Track 3 builds the tour itself:

1. Pick the 5-step tour: citymap → trace → marks → agent graph →
   evaluate. Each step points at one DOM node and emits a one-line
   narration.
2. Wire `CheatSheet.tsx` to a real handler that drives the
   `GuidedTour.tsx` component.
3. Add Vitest coverage for the tour state machine.
4. Persist a `tourSeen` flag in `localStorage` so the tour does
   not re-trigger for users who have seen it.

Estimated: 6-8 hours including frontend design iteration.

### Track 4 — server hardening (the items deferred from T34)

1. Add `TestAgentGraphCacheConcurrentEviction` — verify
   `evictAgentGraphsLocked` does not lose entries under `-race` when
   many in-flight requests push the LRU past 100.
2. Stress-test on a 100k-row Crush fixture to validate the
   cross-message fold loop at scale (the current stress test
   generates row inserts but no cross-message results).
3. Audit `parts.go`'s `agents_test.go:316` cross-message agent-launch
   consumer — does it correctly handle a child session whose
   `agent` tool call's result lives in a parent message?

Estimated: 2-3 hours.

### Track 5 — process + documentation

1. Open the upstream PR for the T06+T07 fix (OutcomeKnown +
   cross-message result pairing). The diff is small, self-contained,
   and well-tested; should land cleanly.
2. Add `docs/MERGE_CHECKLIST.md` link to `CONTRIBUTING.md` so new
   contributors see it before opening a PR.
3. Refresh `AGENTS.md`'s Crush paragraph once Track 2 lands.
4. Refresh `README.md`'s "Session evaluation" once Track 1 lands.

Estimated: 1-2 hours.
