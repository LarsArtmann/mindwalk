Verdict: Good — address cohesion, no urgent restructuring

mindwalk has a fundamentally sound layered architecture. The model package is a pristine zero-dependency data contract layer. The instability gradient points the right way: stable leaf packages (model, textutil) at the bottom, the maximally unstable server at the top. The adapter boundary (Source interface) cleanly isolates four heterogeneous agent log formats. There are no Go import cycles. The one structural debt worth paying down: two god-files (adapter.go, server.go) that mix multiple bounded contexts, and a conceptual judge↔adapter dependency inversion.

♦Strengths

+
Pristine model layer internal/model is pure data contracts with zero dependencies and zero behavior. The hardest layer to get right is the one that never changes — this one is correct.
+
Correct instability gradient Stable leaf packages (model I=0.00, textutil I=0.00) at the bottom; maximally unstable server (I=0.89) at the top. The dependency skeleton points the right way.
+
Capability-based adapter interface Source, Closer, DiagnosticsSource, AgentGraphSource are small, optional, composable interfaces — composition over inheritance done right.
+
No horizontal adapter coupling The four harness sub-packages (claudecode, codex, crush, pi) never import each other. New formats plug in without touching existing ones.
+
Sealed judge security boundary The judge subprocess gets no tools, no MCP, no user/project config (cli.go:80-155). Untrusted trace content cannot reach the local filesystem. Dependency injection via Runner makes it fully testable.
+
Injectable citymap builder Server.buildCityMap is a function field, not a hardcoded call — tests swap it without mocking. A small but exemplary seam.

04Findings

P1 · High

God-file: internal/adapter/adapter.go (1,355 LOC, 51 functions)

internal/adapter/adapter.go · 51 funcs across 4 distinct concerns

This single file mixes four bounded contexts: (a) the Source/Closer/ DiagnosticsSource interface contracts, (b) path/file utilities (HomePath, OpenFile, NormalizePath), (c) ~1,000 lines of tool-call classification and command parsing (actionFor, targetsFor, verifyCommand, gitDiffTargets, parsePatchPaths, searchCommand, readCommand, JS-paren matching), and (d) agent-graph presentation helpers (OrderAgentNodesPreorder, AgentNodeID).

Fix: Extract the tool-classification subsystem (~1,000 LOC, lines 342–1354) into its own package, e.g. internal/toolclass or internal/event. The interface contracts stay in adapter; the classification logic becomes a dependency of every adapter sub-package. This is a pure move refactor — no behavior change, and the existing tests pin the contract.
P1 · High

God-file: internal/server/server.go (1,422 LOC, 31 methods)

internal/server/server.go · Server struct holds 11 map fields

The Server struct owns five independent caches (traces, agent graphs, summaries, repo maps, session catalog), each with bespoke TTL/eviction/inflight-dedup logic — 11 map fields total. It also handles HTTP routing, session scanning, static asset serving, and adapter construction. Every new endpoint or cache grows this file further.

Fix: Extract a generic cache<K, V> type (TTL + LRU eviction + inflight singleflight) and give each cache its own small wrapper. Move the caching layer into internal/server/cache.go or a dedicated sessionstore package. The HTTP handlers and scanning logic can stay in server.go but call into the extracted store.
P1 · High

Dependency inversion: adapters depend on judge

internal/adapter/codex/adapter.go:163, internal/adapter/crush/sessions.go:199

adapter/codex and adapter/crush call judge.IsWorkDir() to filter out mindwalk's own judge-run sessions from the rail. This makes the parsing layer depend on the evaluation layer — a conceptual cycle between two bounded contexts. The adapter should not know the judge exists.

Fix: Move IsWorkDir / WorkDir into a neutral package (e.g. internal/mindwalk or the existing internal/adapter alongside MindwalkHome), then filter self-sessions in the server's scanSessions (which already owns the catalog) rather than in each adapter. Alternatively, expose a SessionMeta.Auxiliary flag the server sets post-scan.
P2 · Medium

citymap shells out to git with no interface abstraction

internal/citymap/builder.go:91, 256, 262

Builder.Build calls exec.Command("git", ...) three times directly (ls-files, rev-parse, status). There is no interface to swap, so the builder cannot be tested without a real git repository, and a future "no-git" mode (plain directory, SVN, etc.) would require editing the builder.

Fix: Define a FileLister interface (ListFiles(root) ([]string, error)) and a VCSInfo interface (Commit(root) / Dirty(root)). The default implementation shells out to git; tests inject a fake. Keep the current git behavior as the production default.
P2 · Medium

Frontend god-component: App.tsx (966 LOC, 74 hooks)

web/src/App.tsx

App.tsx holds 74 useState/useEffect/useMemo/ useCallback/useRef calls in a single component. It manages session loading, playback, agent graphs, report streaming, scene selection, and panel layout simultaneously. The existing state/store.ts (Zustand) is only lightly used.

Fix: Migrate server-fetch and playback state into the Zustand store (already present at state/store.ts). Extract useSession, usePlayback, useReportStream custom hooks. Target <300 LOC for App.tsx.
P3 · Low

jsonschema is a production dependency used only in tests

go.mod:6 · only caller: internal/model/agent_schema_test.go

github.com/santhosh-tekuri/jsonschema/v6 is listed as a direct dependency but is referenced exclusively by agent_schema_test.go. The schema/ JSON files are unvalidated at runtime — they are documentation contracts, not enforced. This inflates the production dependency surface.

P3 · Low

Adapter registration is hard-coded

internal/server/server.go:1391 (buildAdapters)

buildAdapters hard-codes the four-adapter list. Adding a fifth harness requires editing server.go (and cmd/mindwalk flags). A registry/init pattern or a constructor slice in cmd/mindwalk would keep the server agnostic. Minor — the list is small and changes rarely.

Bug · not architectural

Unchecked rows.Err() after rows.Next() loop

internal/adapter/crush/sessions.go:914-920

gopls flags a sql.Rows loop at sessions.go:914 that never checks rows.Err() after iteration. A silent DB error mid-scan would be swallowed. Not an architecture issue, but surfaced during this review.

05Action Roadmap

1

Break the judge↔adapter inversion

Move WorkDir/IsWorkDir to a neutral home (the adapter package alongside MindwalkHome, or a new internal/mindwalk). Filter self-sessions in server.scanSessions rather than in each adapter. Deletes two judge imports from the adapter layer.

P1 Effort: S Impact: High No dependencies
2

Extract tool-classification into its own package

Move ~1,000 LOC of tool-call semantics (actionFor, targetsFor, verifyCommand, gitDiffTargets, parsePatchPaths, SummarizeTool, BuildEvent) from adapter.go into internal/toolclass (or internal/event). Pure move refactor; the existing adapter_test.go suite pins every behavior.

P1 Effort: M Impact: High After step 1 (cleaner import graph)
3

Extract a cache layer from server.go

Introduce a generic cache[K, V] with TTL + LRU + singleflight inflight dedup. Wrap each of the five server caches (traces, agent graphs, summaries, repo maps, session catalog) as a thin type over it. Cuts server.go from 1,422 to ~600 LOC and makes cache behavior consistent and independently testable.

P1 Effort: M Impact: High No dependencies
4

Abstract the git dependency in citymap

Define FileLister and VCSInfo interfaces in citymap. Default implementation shells out to git (current behavior). Tests inject fakes. Enables a future no-git directory mode.

P2 Effort: S Impact: Medium No dependencies
5

Decompose App.tsx

Migrate fetch/playback state into the existing Zustand store. Extract useSession, usePlayback, useReportStream custom hooks. Target <300 LOC for App.tsx. Enables parallel frontend work without merge conflicts.

P2 Effort: M Impact: Medium No dependencies
6

Move jsonschema to indirect / test-only

Run go mod tidy to mark jsonschema/v6 as indirect (it is only imported by test code). Keeps the production dependency surface honest.

P3 Effort: S Impact: Low No dependencies

What NOT to do

Do not split into microservices

mindwalk is a local single-binary tool. The monolith with clear internal module boundaries is the correct architecture. Service extraction would add operational complexity with zero benefit. The "Service Orientation: 3/5" score reflects the right design for the wrong question — a local tool should not be service-oriented.
